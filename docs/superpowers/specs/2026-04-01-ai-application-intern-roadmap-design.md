# 2027 届 AI 应用开发实习项目冲刺路线设计

## 1. 目标

本设计文档用于收敛 `企业文档智能协作平台 MVP` 的 6 到 8 周冲刺路线，目标不是把项目做成完整平台，而是把它打造成一个对 `AI 应用开发实习` 足够有说服力的高含金量项目。

路线设计必须满足以下原则：

- 优先体现 `RAG`、`Multi-Agent`、`Prompt Engineering`、`结构化输出`、`流式状态同步`
- 每一阶段都必须形成端到端闭环，而不是长期停留在底层基建
- 尽量复用现有优势：`Go`、异步任务、`Redis Streams`、`WebSocket`
- 第一版只做最小业务闭环，不被多租户、复杂权限、真实外部写回拖慢

## 2. 推荐路线

本项目推荐采用：

`AI 闭环优先，平台能力后置`

不推荐优先做重平台基建，也不推荐优先做重前端包装。原因如下：

- 面试官首先会判断这是不是一个真正的 `AI 应用`，而不是普通 CRUD 项目叠了一个模型接口
- 你的个人优势在于把传统后端可靠性和异步能力引入 AI 工作流，而不是做一个常规管理后台
- 在 6 到 8 周窗口内，最重要的是尽快做出 `可解释、可审批、可执行、可观测` 的 AI 闭环

因此推荐优先级固定为：

1. `RAG + citation`
2. `Eino DAG + structured output`
3. `Redis Streams + WebSocket` 驱动任务流式状态
4. `Approval + ExecutionJob` 闭环
5. `Eval + audit + demo packaging`

## 3. 阶段划分

### Phase 1: RAG 最小闭环

目标是先让系统具备“能读文档、能检索、能引用证据”的核心 AI 能力。

范围：

- 只支持平台内 demo 文档
- 使用 Markdown-aware chunking
- 用 `PostgreSQL + pgvector` 建立最小检索能力
- 返回 citation payload 并在前端展示

这一阶段的关键不是资源 CRUD，而是让系统具备可追溯检索能力。

### Phase 2: Eino Multi-Agent DAG 与结构化修订提案

目标是做出真正体现 AI 工程能力的智能链路。

范围：

- 用 `Planner -> Retriever -> Reviewer -> Editor` 固定成可控 DAG
- 强制 `Editor` 输出结构化 JSON
- 用结构化结果渲染 `review summary`、`citations`、`change proposals`、`diff preview`
- 为模型输出增加解析校验、重试和最小修复机制

这一阶段的重点不是把模型“聊顺”，而是把结果压成稳定的机器可消费格式。

### Phase 3: 流式可观测性与任务实时同步

目标是把传统后端异步技术优势转化成 AI 项目亮点。

范围：

- 建立 `Task / TaskStep / TaskArtifact` 最小任务模型
- 将 Agent 各节点状态事件写入 `Redis Streams`
- 用 `WebSocket` 向前端实时推送任务进度与中间产物
- 支持步骤级状态可视化和断线后按 Stream ID 补发

这一阶段的重点是展示“长耗时 AI 任务如何被工程化地实时观测”。

### Phase 4: 审批与异步执行闭环

目标是把 AI 输出纳入企业场景可控执行链路。

范围：

- 建立 `Approval`、`ExecutionJob`、`ResourceVersion`
- 审批通过后由后台异步 Worker 执行，而不是同步执行
- 使用 `Redis Streams consumer group` 实现执行队列、重试与接管
- 执行成功后生成新的平台内文档版本

这一阶段的重点是把“AI 建议”升级为“可审批、可执行、可追溯”的业务闭环。

### Phase 5: 评测、稳定性与简历包装

目标是把项目从“能跑”打磨为“能讲、能验证、能抗问”。

范围：

- 固定一组 demo 文档和评测 case
- 评估 citation 命中、结构化输出成功率、diff 可用率
- 补充审计、回放、回归验证
- 固化本地演示方式与 README 表达

这一阶段的重点是建立证据，证明项目不仅存在，而且可靠。

## 4. 技术亮点的平移方式

### 4.1 Redis Streams

该项目中不应只把 Redis 当缓存使用，而应承担两类核心职责：

- `Agent workflow event bus`
- `Execution job queue`

推荐用法：

- `XADD` 写入任务与步骤事件
- `XREADGROUP` 驱动 Worker 和实时状态消费者
- `XPENDING / XCLAIM` 处理超时与接管
- 用业务幂等键防止重复执行

这样可以把你熟悉的分布式消息与异步任务经验，直接转换为 AI 工作流亮点。

### 4.2 WebSocket

`WebSocket` 负责把 AI 工作流从“后台黑盒”变成“前台可观测过程”。

推荐展示的能力：

- 当前任务状态推进
- 当前执行节点
- 中间产物流式更新
- 断线重连后的增量补发

这会让面试官很容易把你归类为“懂 AI 编排，也懂工程落地”的候选人。

## 5. 成功标准

6 到 8 周冲刺完成后，项目至少应满足：

- 用户能浏览平台内 demo 文档并进行 citation 检索
- 用户能发起“审阅与修订”任务，并获得结构化审阅结果和 diff 预览
- 前端能实时看到 Agent 工作流的执行进度和中间状态
- AI 生成结果不会直接落地，而是进入审批
- 审批通过后，系统异步执行并生成新的文档版本
- 项目具备基础评测、审计和可复现 demo 能力

## 6. 设计结论

在 2027 届 AI 应用开发实习求职语境下，这个项目最有价值的表达不是“大而全平台”，而是：

`把可解释的 AI 提案纳入可审批、可异步执行、可实时追踪的任务闭环。`

路线设计必须始终围绕这句话服务。
